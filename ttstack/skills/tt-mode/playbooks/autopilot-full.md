### Autopilot-full

**You own the verdicts, never the PRs. One owner runs each PR from build to merge. Nothing merges without your clean swarm verdict.** For "autopilot this queue", "full autopilot", "merge them yourself". Independent PRs with landing authority granted. Orchestrate is the standing-program shape whose coordinator lands work and whose workers never merge. Here each PR's owner carries the lifecycle through the merge, and the root keeps verification and audits.

1. **Mark the operator's items and wait for go.** Items the operator names stay with the operator. The operator reviews and clicks. When the operator asks for the protocol or the plan, deliver it and stop. Execution starts only on the operator's explicit go. On that go, arm `/loop 1h` for the audit tick. The prompt names the plan path, who merges, and the done condition. A run with no plan file names the queue in place of the path.
2. **Spawn one owner per PR.** One cloud agent per PR builds the change, opens the PR per **Opening a PR**, proves it on the real surface (the **prove-it-works** principle skill), and babysits to green per **Babysit** (`playbooks/babysit.md`). No Graphite. After the PR is open, the owner pushes its branch again after every verifiable unit (hooks on, a WIP commit is fine). The owner does not merge until step 5. As soon as a subagent starts, the owner adds its ID, expected runtime (at least the longest past run of that kind), and state to a `children.tsv`. The owner rebases onto current trunk before the code-ready report, whether or not trunk drifted. In fix rounds it keeps that merge base. It rebases again only when step 5's pre-merge checks fail, on a `git merge-tree` conflict with trunk, or on a CI failure that comes from a change on trunk. After `/deslop` and `/no-comments`, it reports the code-ready head SHA, and the SHA of each later push that changes the patch. Self-proof, CI, and babysit then run in parallel with the swarm. The owner reports merge-ready with the head SHA when those finish. To publish a rebase, push the owner's own branch with `git push --force-with-lease` after `ls-remote`. Never force-push a shared branch.
3. **Run owners in parallel. Never stack.** Self-contained PRs branch off `main`. Overlapping work serializes. Sequenced work is merge-then-branch. One writer per branch (the **separate-before-serializing-shared-state** principle skill).
4. **Swarm-verify every round.** A round starts at the owner's code-ready head SHA and at each later push that changes the patch. Fan out per the **swarm** skill. Lanes re-run the gates at that SHA, prove load-bearing behavior live via the matching control skill or a named driver where none exists, and audit receipts plus the diff while distrusting the PR body. Run the audit as two or more lanes with distinct focus. Consumer parity with trunk, lifetimes and races, data and config safety. The live lane is the floor. Findings go back to the owner. A defect a lane filed as a note is a finding. For each behavior finding, ask for a red test that covers every site with the same defect, or a repro receipt. Add that defect to the next round's brief. A new head gets a fresh swarm except when the patch-id is unchanged.
5. **On a clean verdict the owner merges, and a fresh owner takes the next item.** Merge prep never starts before the round's lanes. Once the head is green and its patch-id matches the verdict, a later trunk move does not force another rebase. Right before the merge, fetch trunk and check that `git merge-tree` of the head against current trunk is clean. Also check that no path in `git diff --name-only $(git merge-base HEAD origin/main) origin/main` is a path the PR changes or a path that decides which CI runs for it. If either check fails, rebase, report the new head SHA, wait for CI on that head, and repeat the checks. A new head voids the verdict unless the patch-id is unchanged. Squash-merge with the host's squash-merge command. The operator's autonomy grant plus the root's clean verdict is the merge authorization. Operator-named items stop at merge-ready. The owner returns. A fresh owner picks up the next self-contained item, per tt-mode's Subagents section.
6. **Run the root audit tick.** Every hour, via that `/loop 1h`, in both local and cloud roots. Do not use a separate cloud sleeper. Re-read this playbook and the plan file the prompt names. With no plan file, re-read the queue and the done condition from the prompt. Count only side effects as progress (commits, pushes, PR or check deltas). Treat a lane that errors, or that passes its expected runtime without a side effect, as stuck. Stand it down and replace it. Each tick sweeps the platform's agent list and every owner's `children.tsv`. The owner records stuck children and replaces them if their work is still needed. The root does both when the owner cannot. End the tick only when no delegated work remains, including after the last merge.
7. **Stand down on the operator's stop.** A hold reaches every owner as a zero-writes order at once.

**Reply:** the queue with each PR's owner, state, and head SHA; each verdict; what merged and what each fresh owner took next; open operator gates; where the decision trails live.
